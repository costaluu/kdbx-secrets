# 15: `encrypt --to` and `decrypt --key`

**What to build:** Keys start to come from the Database. `encrypt --to <ref>` reads the public key from the Reference's value (normally an Attachment) and combines it with `-r`, with a prompt only if there is `--to`. `decrypt --key <ref>` reads the private key, armored or binary, from the Reference's value and uses the Password of the same Entry only if the key is encrypted. The decrypted text sits in a buffer of up to 64 MiB and is only written after integrity (MDC/AEAD) is verified. A message without integrity protection is refused, one above 64 MiB is refused, and a post-quantum key gives a clear error. The refusal of a tty without `--show` applies to `decrypt`. Compatibility with `gpg` holds in both directions for v4 keys, including gpg 2.5's AEAD/OCB.
